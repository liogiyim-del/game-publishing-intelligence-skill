# UAT 测试场景｜V0.1

## 使用方式
每次修改 Prompt、Schema、路由规则或 HTML 后，至少回归以下场景。

| ID | 场景 | 必须验证 |
|---|---|---|
| UAT-01 | 国家政策 P0 | 官方原文、状态、生效时间、地区影响、未知项、P0快讯标识、Calendar写入、人工审核 |
| UAT-02 | 大型版本/玩法重做 | 前后对照、产品与宣传动态比例、玩家原声、资产矩阵、下一节点 |
| UAT-03 | Convention 高密度期 | 展前/展中/展后路由、多个重要事件收录、首页最多5条、完整目录 |
| UAT-04 | 重大舆情 | 前因、触发、扩散、回应、内容/流程/沟通问题、事实/分析分离、24h/72h更新 |
| UAT-05 | 创意 OOH/UGC | 多图、选址/机制/传播路径、少文字、不虚构投放效果 |
| UAT-06 | 预告信号 | 已确认/高可信/待观察分层，明确升级条件 |
| UAT-07 | 无有效信号 | 不生成业务报告；运行记录可查并说明原因 |
| UAT-08 | 跨期重复事件 | 无新增不进正文；有更新只写新增；旧图/旧数据不重复 |
| UAT-09 | 玩家与数据分歧 | 分别并列展示，不合成为成功/失败判断 |
| UAT-10 | 数据源失败 | 标记未覆盖、使用降级方案、不编造数据 |

## Golden Example 回归

### GE-01 PRAGMATA
必须做到：
- 判断重点是“产品教育/理解问题”
- 机制：兴趣 → 理解 → 试玩验证 → 商店承接 → 购买
- 不把100万/200万销量归因于Demo
- 缺Demo漏斗时维持有限信号

### GE-02 Modern Warfare 4
必须做到：
- 核心机制：预购锁定 → 旧作回流 → 新作迁移
- 5000 Skulls规则与真实活跃效果分开
- 模式积分效率差异只能推出“可能迁移”，不能推出整体DAU增长
- 编号奖励识别为稀缺层，普通奖励为保底层
- 无参与/完成/活跃数据时不能说活动成功

### GE-03 Crimson Desert
必须做到：
- 结论：补丁上线 ≠ 风险关闭
- 区分 Asset / Process / Trust Closure
- 多轮替换只能证明持续修复
- 完整范围、流程修复、最终审计缺失时不能写“已清零”

## 通过标准
- 事实错误：0
- 越界因果：0
- 无依据行业比较：0
- 政策/平台官方原文缺失：0
- 重大舆情三类证据缺失：0
- 同一结论无明显重复
