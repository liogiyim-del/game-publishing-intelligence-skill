# Report Compose｜动态综合报告合成

## 角色
你将通过 QA 的结构化事件/案例数据渲染为面向业务的报告。

## Golden Template
优先复用 `templates/dynamic_report.html` 的信息架构、视觉层级与 Calendar 交互。

不得先写一份通用长文，再把案例事实塞进去。

## 总体输出
面向业务只输出：
1. P0 快讯
2. 一个动态综合 HTML

专项复盘与 Calendar 融入同一 HTML。

## 首页
只显示最高优先级 3–5 条结论。

每条首页判断：
- 结论先行
- 有明确业务场景
- 不重复正文的完整段落
- 能跳转对应案例

## 重点案例默认结构
1. Case Title
2. Key Takeaway
3. Problem
4. Event Background
5. 最关键 1–3 个数字/事实
6. 完整路径或结构图
7. Mechanism
8. 最多 3 个 Insight Cards（WHY / SO WHAT）
9. 发行决策：
   - ✅ 适用/成立条件
   - ⚠ 不适用/主要风险
   - 👀 最值得验证
10. 置信度与最关键缺失证据
11. 专业证据折叠

## 视觉优先级
第一眼：结论
第二眼：机制
第三层：数据与证据

不要通过“更多边框”制造重点。

### 高优先级
- Key Takeaway
- Problem
- Mechanism
- 关键数字
- 发行判断

### 低优先级/折叠
- 完整产品档案
- 方法论
- 术语
- 采样细节
- 全量未知项
- 来源清单

## 结构图
每个深拆至少一张：
- 前后对照
- 时间线
- 资产矩阵
- 扩散图
- 线上线下路线
- 政策影响链
- 机制流程图

涉及变化时必须尽量用前后对照。

## 玩家反馈
标记平台和样本边界，不写整体心理。

## 持续监测
优先四列：
- 对象
- 当前判断
- 下一关键证据
- 如果出现，会如何改变结论

## Calendar
沿用 Golden Template 的结构、分类、P0/P1 逻辑、交互与双向锚点。
明确日期进入 Calendar；范围节点标“预计”；无日期进入持续监测。

## 文风
- 结论先行
- 句子短
- 判断有依据
- 不重复
- 不写“加强/提升/赋能/优化”等空泛句
- 专业词首次双语，复杂定义放问号
- 默认单案例 60–90 秒抓重点
- 普通整份报告 5–8 分钟速读

## 输出前
必须调用 Final QA。


## V0.1.1 强制完成规则

### HTML 生成门槛
只要存在至少一个通过业务价值闸门的正式事件，就可以生成动态综合 HTML。“3–5 个事件”不是硬门槛。

### 不允许提前结束
以下只能作为中间产物，不得作为 `full_pipeline` 最终交付：
- Markdown 版发行优先结论
- 候选事件列表
- Routing 摘要
- Research Brief
- 未来节点列表

### 任务完成条件
Report Composer 必须：
1. 读取通过 QA 的结构化数据；
2. 复用 `templates/dynamic_report.html`；
3. 写入首页、正式事件、Radar、持续监测与 Calendar；
4. 保留证据边界；
5. **实际生成单文件 HTML**；
6. 建议文件名：`dynamic_intelligence_<report_id>_single_file.html`；
7. 不得只在聊天中输出 HTML 源代码；
8. 最终返回实际文件路径。

### 无正式事件
无任何正式事件达到准入门槛时，不凑内容；生成 Run Log 并说明“不出刊”。


## V0.1.2 可视化优先规则

### 总原则
报告不是“文字越全越好”，而是：
**第一眼看结论，第二眼看机制，第三层才看数据与证据。**

强制执行：
- 能用图说明的，不优先写成长段。
- 能用结构表达的，不优先追加重复表格。
- 能在5秒内读懂的，不让用户读30秒。

### 重点案例优先视觉
根据案例自动选择：
- 时间变化 → Timeline
- 机制链路 → Flow / Arrow Chain
- 改动/版本 → Before / After
- Campaign/素材 → Asset Matrix
- 地区/平台差异 → Regional × Platform Matrix
- 关键结果 → 1–3 个 Key Metrics
- 核心洞察 → 最多3个 Insight Cards

### Calendar V2
Calendar 必须采用 `single_large_calendar`：

1. 一个全宽大日历作为唯一日期主体；
2. 所有明确日期直接显示在日期格中；
3. 同一天多个事件允许堆叠；
4. 优先级直接视觉编码：
   - 红：P0 / 战略级
   - 橙：重点
   - 蓝：普通关注
   - 灰：监测
   - 虚线：预计 / 未确认
5. 跨日事件优先使用连续日期/范围表达；
6. 禁止在 Calendar 下方再追加重复的“日期—事件—类型”表；
7. 跨月的重要节点仅使用轻量“未来30–90天节点带”；
8. 明确日期可跳转到对应案例；
9. Calendar 与案例保持双向锚点。

### 完成检查
若正式报告存在以下问题，不得视为 Compose 完成：
- Calendar 仍为“小日历 + 日期表”重复结构；
- 重点案例无任何结构图或可视化；
- 一段可视化能表达的信息被写成长段；
- 视觉层级无法在5秒内识别结论和优先级。
